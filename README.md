# Сервис регистрации на мероприятия (TestMad)

Клиент-серверный сервис для организации мероприятий, регистрации участников, управления листом ожидания (waitlist), выпуска электронных билетов и чекина участников.

---

## 🛠 Стек технологий
- **Backend:** Python 3.11, FastAPI, SQLAlchemy 2.0 (asyncio + asyncpg), Alembic, Pydantic v2, aiosmtplib, APScheduler.
- **Frontend:** React 18, Vite, TypeScript, Lucide Icons.
- **Database:** PostgreSQL 16.
- **Почта (заглушка):** MailHog (SMTP `:1025`, Web UI / API `:8025`).
- **Инфраструктура:** Docker, Docker Compose.

---

## 🚀 Быстрый запуск

### 1. Запуск через Docker Compose (рекомендуемый)
```bash
docker compose up --build
```
После запуска доступны:
- **Frontend:** [http://localhost:5173](http://localhost:5173)
- **Backend API Docs (Swagger):** [http://localhost:8000/docs](http://localhost:8000/docs)
- **MailHog Web UI:** [http://localhost:8025](http://localhost:8025)

## 🧪 Запуск автотестов и демо

### Запуск тестов через Pytest (все 7 тестовых наборов):
```bash
pytest backend/tests -v
```

### Запуск доказательного демо-скрипта:
```bash
python scripts/demo.py
```
Скрипт автоматически определяет, запущен ли сервер локально или через Docker, и пошагово воспроизводит:
1. Создание события с лимитом 2 места.
2. Параллельную гонку 3 запросов на 2 места (Race Condition).
3. Повторную регистрацию на тот же email (Идемпотентность).
4. Отмену регистрации первого участника и автоматический промоут из листа ожидания (FIFO).
5. Чекин на входе и отклонение повторного прохода (409 Conflict).
6. Рассылку напоминания за 24 часа (строго одно письмо).
7. Перенос даты мероприятия организатором и рассылку уведомлений.
Все архитектурные решения, изменения и обоснования фиксируются в файле [DECISIONS.md](./DECISIONS.md).
