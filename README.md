# Сервис регистрации на мероприятия (TestMad)

Клиент-серверный сервис для организации мероприятий, регистрации участников, управления листом ожидания (waitlist), выпуска электронных билетов и чекина участников.

---

## 🛠 Стек технологий
- **Backend:** Python 3.11, FastAPI, SQLAlchemy 2.0 (asyncio + asyncpg), Alembic, Pydantic v2, aiosmtplib, APScheduler.
- **Frontend:** React 18, Vite, TypeScript, Lucide Icons.
- **Database:** PostgreSQL 16.
- **Почта (заглушка):** MailHog (SMTP `:1025`, Web UI / API `:8025`).
- **Инфраструктура:** Docker, Docker Compose.

---

## 🚀 Быстрый запуск

### 1. Запуск через Docker Compose (рекомендуемый)
```bash
docker compose up --build
```
После запуска доступны:
- **Frontend:** [http://localhost:5173](http://localhost:5173)
- **Backend API Docs (Swagger):** [http://localhost:8000/docs](http://localhost:8000/docs)
- **MailHog Web UI:** [http://localhost:8025](http://localhost:8025)

## 📊 Честный статус готовности

| Компонент / Требование | Статус | Комментарий |
|---|---|---|
| Инфраструктура Docker Compose (БД, MailHog, Backend, Frontend) | ✅ Готово | Каркас сервисов собран и сконфигурирован |
| Healthcheck API | ✅ Готово | `GET /api/v1/health` возвращает статус |
| Модели БД и миграции Alembic (Event, Registration, Ticket) | ✅ Готово | Описаны модели SQLAlchemy 2.0, индексы, миграция 0001, seed-скрипт |
| Регистрация по email + генерация билета | ✅ Готово | API `/events/{id}/register`, генерация читаемого `TKT-XXXXXX`, отправка писем через MailHog |
| Идемпотентность повторной регистрации на один email | ✅ Готово | Повторный вызов возвращает существующий билет без создания дубликата места |
| Конкурентность: гонка на последнее место (`FOR UPDATE`) | ✅ Готово | Защита от race condition (`SELECT FOR UPDATE` в Postgres + lock fallback), доказано тестами |
| Лист ожидания (waitlist) при исчерпании мест | ✅ Готово | При заполнении лимита регистрация автоматически получает статус `waitlist` и номер очереди |
| Отмена участия + авто-промоут первого из листа ожидания | ✅ Готово | Эндпоинт `/registrations/cancel/{token}`, строгий FIFO порядок, генерация билета новому участнику |
| Чекин билета по коду + защита от повторного чекина | ✅ Готово | Эндпоинт `/checkin`, защита от повторного прохода (409 Conflict), нормализация кода |
