### Что сделано:
1. Создана структура монорепозитория:
   - `backend/` — каркас микросервиса на FastAPI с Pydantic Settings и Healthcheck-эндпоинтом.
   - `frontend/` — каркас SPA на React 18, Vite и TypeScript.
   - Корневой `docker-compose.yml` и конфигурация `.env.example`.
2. Настроены контейнеры:
   - `db` (PostgreSQL 16 Alpine) с healthcheck (`pg_isready`).
   - `mailhog` (MailHog) для перехвата SMTP-сообщений (`:1025`) и чтения через REST API / Web UI (`:8025`).
   - `backend` (FastAPI/Uvicorn) с монтированием тома для мгновенной горячей перезагрузки (`reload`).
   - `frontend` (Node 20 / Vite dev-сервер) с поддержкой polling для файловых систем Docker.
3. Оформлена базовая документация: честный чеклист статуса в `README.md` и данный журнал решений `DECISIONS.md`.

### Почему выбраны такие решения:
1. **Docker Compose как единая точка запуска:**
   - *Причина:* Полная изоляция зависимостей. Проверяющему не нужно устанавливать локально PostgreSQL или MailHog — всё поднимается командой `docker compose up --build`.
2. **MailHog вместо реального почтового сервера:**
   - *Причина:* Исключает необходимость в реальных SMTP-креденшелах, внешних сервисах (SendGrid, Mailgun) и исключает риск попадания в спам. Предоставляет JSON API, благодаря которому демо-скрипты и автотесты могут проверить доставку писем программно.
3. **FastAPI (асинхронный) + React Vite:**
   - *Причина:* FastAPI нативно поддерживает WebSockets и асинхронную работу с базой через `asyncpg`, что критично для поддержания live-счетчиков и тестирования параллельной конкурентности. Vite обеспечивает быструю сборку и HMR.
